Protomaps: Self-hosting map tiles has gotten cheap and easy
⬆ 447 pts 💬 78 HN comments

Protomaps' PMTiles format collapses an entire planet-scale tile pyramid into a single immutable file that a browser can address through HTTP Range requests, eliminating the tile server entirely. Bruce Röttgers' walkthrough is less a tutorial than an existence proof: download the daily world build (139GB), stream it with rclone into an S3-compatible storage zone on Bunny.net, create a pull zone, enable 'Optimize for large object delivery' so the CDN caches Range requests, and embed with MapLibre GL plus the pmtiles npm package. The economic argument is the real payload — $5/month in storage at 5x continental replication, roughly 5MB of transfer to load and zoom into a European city, and an implied $0.05 per 1k map loads against Mapbox's $5 per 1k after the free tier. Map infrastructure shifts from a metered API dependency to a static asset with a rounding-error cost ceiling.

The operational details are where the engineering value sits. Röttgers notes the HTTP upload API timed out after 15 minutes, so S3 compatibility plus chunked streaming is mandatory; CORS via allowed referrers stops third-party embedding; a 10kB/s throttle after 10MB per request discourages whole-file scraping that would inflate the CDN bill. Cloudflare requires an edge function to translate x/y/z paths into Range requests, and the comments surface the format's real failure modes: a corporate anti-malware proxy that silently stripped the Range header and fetched the whole file, client-side Range caching that is unpredictable and unstandardized, and the fact that raster satellite mosaics blow past the 'stick it on R2' regime into hundreds of terabytes at z17+. The broader signal is that a commoditized base-map layer — vector OSM data, static hosting, open clients — has become table stakes, while differentiation migrates upward into styling, freshness, and query semantics.

Storing the full 139GB world map with continental replication costs about $5/month, and per-load bandwidth lands near $0.05/1k — potentially 100x cheaper than Mapbox's flat $5/1k map loads.

Key Highlights
  • PMTiles ships the whole tile pyramid as one file addressable by HTTP Range requests, removing the tile server and turning maps into static assets on any S3-compatible bucket or CDN.
  • Bunny.net's support for caching Range requests makes deployment a download-and-upload operation; Cloudflare instead needs a Worker translating x/y/z paths into Range headers.
  • Cost math is the driver: ~$5/month storage for the 139GB world at 5x replication, ~5MB per interactive city-level session, and roughly 100x cheaper per load than Mapbox's $5/1k.
  • Real-world breakage comes from infrastructure, not the format: proxies stripping Range headers, browser/server caching of partial responses, and upload APIs timing out on multi-hundred-GB files.
  • The self-hosted base-map layer is commoditized across PMTiles/Protomaps, OpenFreeMap, and VersaTiles, with differentiation shifting to styling, data freshness, and reverse-geocoding queries against raw tiles.

#2
Handwriting, as a Font
⬆ 427 pts 💬 72 HN comments

Ductus, a weekend project by Soren Blank, is a browser-based tool that converts handwritten glyph samples into an installable font. The workflow is deliberately minimal: the user writes each lowercase and uppercase letter, digit, and punctuation mark on a canvas using a mouse, trackpad, stylus, or finger; the app captures the strokes, converts them into vector outlines, assembles a glyph set, and lets the user preview and export the result. Ductus claims processing happens locally on the device and nothing is uploaded. Technically, this compresses a classic type-design pipeline—sample acquisition, tracing, contour cleanup, glyph mapping, and font packaging—into a client-side web application. It is not a full font editor, but it demonstrates how modern browser vector and file APIs can put a formerly specialist workflow into a short, accessible loop: find your letters, adjust, export. The HN reaction reflects that shift from novelty to practical tool.

At 427 points and 72 comments, the thread is less a debate about whether Ductus works than about what 'your handwriting as a font' should mean. Fans report completing the alphabet in under three minutes on a phone, then exporting the .otf and emailing it to themselves. The failures are equally concrete: Safari/iPad users saw lowercase previews only, with export greyed out; others hit JavaScript errors such as 'Unable to find segment ... in SweepLine tree' and 'Unable to complete output ring,' exposing fragile polygon-boolean or contour-closing code. The product gap is OpenType depth: no contextual alternates, ligatures, kerning, cursive joining, accented glyphs, or custom symbols. Privacy also surfaces because handwriting is biometric-adjacent—despite local processing, users note absent terms and embedded metadata identifying Ductus.

The most revealing signal is social, not technical: users completed a full glyph set in under three minutes on a phone, yet the thread's dominant request was for contextual alternates and ligatures—the features that distinguish a font from a set of traced letters.

Key Highlights
  • Browser app captures each handwritten glyph and exports an installable font locally.
  • Community praises speed and usability—under three minutes on a phone—and nostalgia for 1990s mail-in font kits.
  • Missing OpenType features: contextual alternates, ligatures, kerning, and cursive joining.
  • Coverage gaps include accented characters, currency symbols, custom glyphs, and image-upload workflows.
  • Reliability and privacy concerns: Safari export failures, SweepLine/contour errors, and handwriting as a biometric fingerprint.

#3
What's Next for Nvidia?
⬆ 418 pts 💬 530 HN comments

Steve Blank's analysis of Jensen Huang's abrupt exit from Nvidia is less a eulogy than an architecture review of a company built around a single decision-making node. Huang's three reinventions — CUDA in 2006, funded for years ahead of any revenue; the 2012 pivot to deep learning after ImageNet; and the 2020 Mellanox acquisition that converted a board vendor into a rack-scale systems company — were business-model transitions, not product refreshes, and Blank argues none of them would have survived a CEO optimizing an existing P&L. The structural tell is organizational: roughly 60 direct reports, no one-on-ones, no long-term plans, no anointed successor, and a board chaired for the first time in its history. The CEO role at Nvidia was never a box on an org chart — it was the point where silicon, software, and go-to-market converged.

The Ballmer/Cook comparison carries the analytical weight. Ballmer tripled Microsoft revenue to $78B while missing search, smartphones, mobile OS, media, and cloud; Cook grew Apple from $108B to $416B and delivered Apple silicon, but produced no new market and outsourced Siri's repair to Google. Blank's fear is mechanistically specific: the 60-report span forces the next CEO to add management layers, and the ~$50B in AI-lab investments plus the annual chip cadence are precisely the bets an executor trims first. Meanwhile the moat is being attacked from below — Google, Amazon, Microsoft, Meta, OpenAI, and Tesla all ship custom ASICs — and the successor inherits a chip-diversion-to-China investigation. Order book and CUDA buy two to three years regardless of who sits in the chair.

Blank's thesis compresses to one line: "Execution pays your salary, innovation pays your pension" — and with ~60 direct reports and no anointed successor, Nvidia's board must decide which one it is actually hiring for.

Key Highlights
  • Huang executed three business-model pivots (CUDA 2006, deep learning 2012, Mellanox rack-scale 2020), none of which a pure operator would have funded ahead of revenue
  • The 60-direct-report, no-succession-plan structure makes the CEO role non-transferable and guarantees the next leader adds management layers
  • Microsoft under Ballmer and Apple under Cook are the canonical failure/success modes: revenue compounding masking missed platform shifts
  • Nvidia's $50B AI-lab investments and annual chip cadence are the highest-risk bets an execution CEO would prune first
  • Hyperscaler custom silicon (TPU, Trainium, Maia, MTIA, Jalapeño) plus a China diversion probe compress the window for reinvention

Old Bitly links are being hijacked
⬆ 364 pts 💬 186 HN comments

Bitly's back-half namespace turned out to be a recyclable resource rather than a permanent one. The mechanism is simple and doesn't rely on a breach: a bit.ly link's suffix (the "back-half") is supposed to be permanently retired when a link or its owning account goes inactive, but on 14–15 November 2026 someone re-registered a batch of suffixes attached to long-dead tweets. The Burger King link in a 24 July 2011 restaurant-locator tweet was reissued at 05:32 UTC and pointed at Wikipedia's list of Nazi concentration camps; a McDonald's Sweden link from 7 June 2011 was reissued 18 minutes earlier and pointed at the September 11 attacks article. Neither brand's account was touched — nothing was posted, no credentials stolen. Anyone holding an archived tweet, email, PDF or printed QR code inherited a new destination chosen by whoever claimed the suffix. Bitly's own +-suffixed info pages, which expose creation timestamps, are the forensic key: a link inside a 2011 tweet cannot honestly show a 2026 creation date.

Ransomnews checked 97 bit.ly links in @realDonaldTrump tweets from 2009–2013: only 40 remain original, while 57 were re-created years after the fact. Forty-nine of those still lead where the tweets intended — 48 of them created in a 17-minute burst (14:55–15:12 UTC, 26 May 2023), apparently a repair job — while seven lead somewhere else and one is blocked as malicious. The going-somewhere-else set included a Roblox profile, a YouTube video, and domains squatting on Trump-family crypto brands (worldlibertyfinancial-ai[.]com, dappradars[.]website, one letter off DappRadar). Bitly acknowledged the issue at 19:13 UTC, suspended the accounts and began deactivating links; CNN later reported the same pattern in old posts from Bill Gates, Trudeau, Pence, the FBI and the DoD. The lasting lesson is that shorteners are unversioned, mutable indirection rented from a third party — and deletion promises are only as good as their enforcement.

57 of 97 Bitly links in Trump's 2009–2013 tweets no longer point where the tweet said — and 48 replacements were created within a single 17-minute window in May 2023, suggesting someone silently "repaired" the namespace years before anyone noticed.

Key Highlights
  • Bitly back-halves of expired/inactive links were re-registered, redirecting decades-old tweets without touching any brand account
  • Burger King (2011) and McDonald's (2011) links were reissued 18 minutes apart and pointed at Wikipedia pages, suggesting a single actor
  • Bitly's public '+'-suffixed info pages expose link creation timestamps, enabling forensic detection of re-created links
  • Bitly confirmed the issue, suspended accounts, and deactivated links; CNN found the same pattern at Gates, Pence, FBI and DoD posts
  • The root failure is unversioned third-party indirection: link ownership is a namespace lease, not a permanent commitment

Preserving 30 years of Salon journalism
⬆ 201 pts 💬 55 HN comments

The Internet Archive's announcement is less a eulogy for Salon than a demonstration of what three decades of continuous crawler coverage actually buys you. Salon launched in 1995 as one of the first publications native to the web, migrated across salon1999.com, salonmag.com and — since 1999 — salon.com, and is now ceasing publication after 31 years. Because the Wayback Machine has been capturing those hosts for nearly the entire run, more than 250,000 article captures remain discoverable, spanning roughly 20,000 distinct bylines. The Archive has layered an experimental 'Salon Explorer' front-end on top of that crawl corpus, offering faceted browsing by writer and topic over an index that was never designed to be queried as a library catalog. Architecturally, this is significant: the recovery is a byproduct of opportunistic, timestamped HTTP snapshots, not editorial intent or a CMS export, which means the record is rich but lossy — missing assets, dead embeds, pagination gaps and layout drift all travel with the content.

The HN thread surfaces the tension that always accompanies web archiving: preservation of the artifact is not preservation of the community. Commenters recalled Salon's own cavalier disposal of its International Issues subforum and later the whole of TableTalk, noting that a publisher which shed its comment infrastructure without export is now itself dependent on a third party's snapshots. Others pressed on the economics and mechanics — why a domain goes dark rather than being parked or sold, whether ad revenue cannot cover what is mostly described as 'administration costs/efforts,' and how one practically wgets a few hundred pages without tripping rate limits or getting temporarily IP-banned. The thread also carries the expected quality asterisk: the claim that the 30-year span is 'not sure... journalism' throughout, and the sharper jab about '15 years of journalism and 15 years of horrible Mary Elizabeth Williams slop.' Nostalgia, tooling complaints, and archival gratitude coexist uneasily, which is roughly the correct emotional register for the moment.

250,000+ Salon articles and some 20,000 bylines survive not because Salon exported them, but because the Wayback Machine happened to be crawling those hostnames for 27 years — a library assembled as a side effect of snapshotting.

Key Highlights
  • Salon ran 31 years across salon1999.com, salonmag.com and salon.com; the Wayback Machine captured all three, yielding 250,000+ discoverable articles and ~20,000 writers.
  • The Archive shipped an experimental 'Salon Explorer' interface to make faceted browsing of crawl data feasible instead of relying on raw timestamp lookup.
  • Commenters note Salon destroyed its own community assets — the International Issues subforum and TableTalk — without offering preservation help, while now relying on a third party for its own survival.
  • Domain shutdowns are questioned as irrational: hosting is cheap, but commenters argue the real cost is ongoing administration, and NXDOMAIN outcomes are common where sale or parking fails.
  • Practitioners describe bulk-retrieval pain: small personal blogs (40 pages) required scripts and triggered temporary IP bans, and 30-year-old reference material like Kryptos K4 threads suffers link and content bitrot.

The HN item titled "A short explainer on how El Niño works [video]" points to a YouTube video that commenters identify as "El Niño Winter 2026–27: What Pilots Should Expect." The captured page text is only YouTube boilerplate, so the substantive story is the thread's reaction: a universal-sounding climate primer is actually a U.S. aviation winter-hazards briefing. Technically, El Niño is the warm phase of ENSO, marked by anomalous sea-surface temperatures in the central/eastern equatorial Pacific, a weakened Walker circulation, eastward Kelvin waves, and shifted tropical convection. Forecasters track Niño3.4 anomalies, ocean heat content, and coupled model ensembles; those tropical signals alter the extratropical jet and storm tracks via teleconnections, translating into turbulence, icing, crosswind, and routing risks for pilots. That operational translation is technically legitimate but narrower than the title implies, which is precisely what the HN audience seized on.
