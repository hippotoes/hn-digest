Peopleless economy? Not technically impossible
⬆ 221 pts 💬 399 HN comments

The article 'Peopleless economy? Not technically impossible' explores a thought experiment where advanced AI and robotics automate all productive labor, leading to an economy that functionally excludes the majority of humans. The core premise is that if machines can produce everything humans currently provide — from farming to software engineering — then human labor loses its economic value. The author argues that this is not a futuristic fantasy but a logical endpoint of current trends in automation, where capital (owned by a few) becomes the sole driver of production. The essay raises unsettling questions: without widespread employment, how would the masses earn income? Would governments implement universal basic income, or would they resort to authoritarian measures to suppress unrest?

The Hacker News discussion, sparked by this provocative thesis, reveals a deeply polarized community. The debate frequently invokes historical parallels, such as the Industrial Revolution, and sci-fi references like Iain Banks' 'The Culture'. A recurring critique is the overconfidence in predicting economic outcomes, with 'andrewmutz' advising to listen to economists, not software engineers.

What AI really seems to be poised to do is make labour a lot less valuable and capital a lot more valuable.

⬆ 1102 pts 💬 476 HN comments

This Hacker News discussion reveals a vibrant community of developers actively replacing cloud-based coding assistants like Claude and GPT with local LLMs. The primary drivers are data privacy, unrestricted usage, and long-term cost avoidance. The consensus is that local models perform comparably to frontier models from 8-12 months ago, sufficient for the majority of daily coding tasks, though complex refactors and UI polish may still require cloud fallback.

Key data points include a user citing $4,400 for dual RTX 3090s equals 3.6 years of $100/m Claude subscription, and another achieving 800 tok/s on a Strix Halo 128GB (laptop chip) with negligible electricity. Several commenters emphasize that the limiting factor is not model quality but harness ergonomics, with Pi and OpenCode receiving praise for their feature set. The community also highlights the importance of quantization and pruning to fit consumer hardware. Societally, this trend democratizes access to advanced coding AI, reduces dependence on a few providers, and raises questions about energy efficiency—local inference on optimized hardware can be net-efficient. However, the opportunity cost of tinkering and upfront hardware investment remains a barrier for many.

A backdoor in a LinkedIn job offer
⬆ 1311 pts 💬 248 HN comments

A sophisticated supply-chain attack targeting developers through LinkedIn was detailed by Roman Imankulov. A fake recruiter from a crypto startup sent a GitHub repository supposedly needing a deprecated Node modules fix. The repository contained a backdoor in app/test/index.js that assembled a URL to a remote server and executed fetched payloads via npm's automatic prepare script on npm install. The author avoided infection by using a Hetzner VPS and a read-only AI agent (Pi) to review the code, which immediately flagged the suspicious file. The trap exploited trust in interview processes and the default npm behavior of running arbitrary code.

The attacker used two stolen identities: a real developer's name on GitHub commits and a journalist’s LinkedIn profile. When the author feigned installation issues, the 'recruiter' suddenly demonstrated deep Node.js expertise, revealing the sockpuppet. The author reported the repo to GitHub and the profile to LinkedIn, but initially no action was taken—though a GitHub staffer later commented that the repos were taken down. The incident highlights how AI-assisted code review can detect such threats, while community comments noted similar scams targeting npm maintainers and the Lazarus Group's involvement. The attack vectors underscore the need for sandboxed environments and skeptical handling of unsolicited job tasks.

“I spun up a throwaway VPS on Hetzner, cloned the repo there, and pointed Pi at it in read-only mode… The agent flagged it in seconds.”

Key Highlights
  • Backdoor hidden in a test file executed via npm's `prepare` script on `npm install`.
  • Attacker used stolen GitHub and LinkedIn identities to build credibility.
  • Author avoided infection by using a read-only AI agent on a disposable VPS.
  • GitHub and LinkedIn initially slow to remove the malicious repo and fake profile.

#2
Iroh 1.0
⬆ 1260 pts 💬 381 HN comments

Iroh 1.0 introduces a paradigm shift in networking by using cryptographic keys instead of IP addresses for connectivity. Developed over four years, this Rust-based library builds on top of QUIC to provide secure, direct peer-to-peer connections that work across NATs, firewalls, and unstable network conditions. Its key abstraction—dialing by key rather than IP—enables devices to remain reachable regardless of location, addressing the fragility of IP addresses and the constraints of traditional networking. The library supports multipath QUIC, integrated NAT traversal, custom transports (BLE, LoRa, Tor), and local-first configurations, making it a modular stack for application-level networking. Iroh is already powering real-time sync, video streaming, distributed AI, and IoT applications, with over 200 million endpoints created in the last month alone.

The 1.0 release marks API and wire protocol stability, with official language bindings for Python, Node.js, Kotlin, and Swift, enabling easy embedding into mobile and web applications. Notably, 95% of data traverses direct p2p paths, reducing cloud egress costs and network hops. The project maintains public relays (with support ending for older versions by end of 2026) and offers hosted services for enterprise users. Comments on Hacker News highlight Iroh's role as ‘Tailscale at the application layer,’ enabling app developers to build secure p2p features without requiring users to manage VPN accounts. This release positions Iroh as a foundational technology for a more decentralized and resilient internet, where applications can communicate directly without central infrastructure.

Dial keys. Not IPs. — Iroh's core abstraction, turning the internet into a secure localhost with 95% direct connections.

Key Highlights
  • Iroh uses Ed25519 cryptographic keys for addressing and securing connections, replacing IP addresses.
  • Built on QUIC with multipath support, NAT traversal, and custom transport hooks (BLE, LoRa, Tor).
  • First stable release with API/wire protocol stability and bindings for Python, Node.js, Kotlin, and Swift.
  • Over 200 million endpoints created in the last 30 days; 95% of data travels direct p2p paths.
  • Public relay support for v1.0 until EOL; older versions deprecate through 2026.
