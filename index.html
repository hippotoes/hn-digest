⬆ 242 pts 💬 103 HN comments

PrismML's 1-bit Bonsai models represent a significant advancement in neural network quantization, pushing the boundaries of efficiency by employing 1-bit weights with shared 16-bit scale factors every 128 bits, effectively operating at ~1.125 bits per parameter. Unlike traditional post-training quantization, these models are engineered from the ground up for ultra-dense intelligence, targeting edge computing, robotics, and real-time agents. The technical foundation lies in optimizing intelligence per bit over sheer parameter count, leveraging research from Caltech to maintain competitive benchmark performance while drastically reducing memory footprint and energy consumption. This approach challenges conventional float-based ML theory, hinting at a paradigm shift where binary or low-precision arithmetic could become standard, driven by the need for sustainable and deployable AI in resource-constrained environments.

Key data points include the Bonsai 8B model requiring only 1.15GB of memory—14× less than full-precision equivalents—while achieving 8× faster inference and 5× better energy efficiency, as claimed in the article. Axios compromised on NPM – Malicious versions drop remote access trojan
⬆ 1837 pts 💬 738 HN comments

The Axios supply chain attack represents a highly sophisticated compromise in the npm ecosystem, where malicious versions 1.14.1 and 0.30.4 were published using a hijacked maintainer account. Unlike typical malware injections, the attack leveraged a fake dependency, plain-crypto-js@4.2.1, which introduced no code changes to Axios itself but executed a postinstall script to deploy a cross-platform remote access trojan (RAT). This approach bypasses source code analysis, as the malicious payload is entirely contained within the dependency's lifecycle scripts. The attacker's precision is evident in the staged dependency publishing, bit-for-bit identical library files, and rapid C2 communication within seconds of installation. This incident highlights the vulnerabilities inherent in npm's trust model, where compromised credentials can lead to widespread infections without altering core package code, challenging traditional security scanning methods.

Key data points include the attack timeline: plain-crypto-js@4.2.1 was published 18 hours in advance, with malicious Axios versions live for under three hours before npm intervention. The dropper, setup.js, employed XOR and base64 obfuscation to evade detection, contacting C2 server sfrclak.com:8000. As noted in the article, 'There are zero lines of malicious code inside axios itself, and that's exactly what makes this attack so dangerous.' Societally, this breach affects over 100 million weekly downloads, prompting discussions on Hacker News about dependency bloat, with comments like 'Batteries included ecosystems are the only persistent solution' and practical tips such as setting `ignore-scripts=true` in npmrc. The incident fuels broader debates on supply chain security, credential management, and the need for ecosystem-wide reforms like Trusted Publishing to mitigate future attacks.

Within two seconds of npm install, the malware was already calling home to the attacker's server, illustrating the rapid execution and sophisticated design of this supply chain compromise.

Key Highlights
  • Malicious Axios versions 1.14.1 and 0.30.4 were published via a compromised npm account.
  • The attack injected plain-crypto-js@4.2.1, a fake dependency with a postinstall script deploying a cross-platform RAT.
  • Sophisticated obfuscation and anti-forensics techniques were used, including self-deletion and version spoofing.
  • Detection was enabled by StepSecurity's AI tools, and npm responded by unpublishing the malicious versions.
  • The incident underscores critical vulnerabilities in npm's publishing security and the broader JavaScript dependency ecosystem.
