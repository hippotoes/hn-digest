Signing data structures the wrong way
⬆ 102 pts 💬 45 HN comments

The article addresses a persistent cryptographic vulnerability: domain separation failures in data structure signing, where distinct message types serialize to identical bytes, enabling forgery attacks. It critiques ad-hoc mitigations in systems like Bitcoin, TLS, and AWS, highlighting how attackers can exploit type confusion—for instance, misusing a signed TreeRoot as a KeyRevoke. The core technical issue is the lack of canonical encodings and explicit type binding in protocols like protobufs, which omit message names in serialization. This context underscores the need for systematic solutions that cryptographically enforce agreement on data 'type' beyond mere content, a problem exacerbated by the rise of authenticated encryption and distributed systems.
