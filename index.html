Show HN: A working Nintendo in ~1GB of Qwen weights
⬆ 269 pts 💬 132 HN comments

nesformer, a Show HN project by dbreunig, compiles a complete NES CPU — the 6502 core of the 2A03 — plus 2 KB of work RAM and a 32 KB PRG-ROM into the weights of a stock Qwen3.5 checkpoint, with no training of any kind. It builds directly on Qwenputer (Divyansh Agrawal), which compiled CHIP-8 and a RISC-V core into Qwen3.5-4B, and reuses its central insight: each Gated DeltaNet head holds a 128×128 state matrix updated by the delta rule, so a one-hot key with the gate held open overwrites exactly one row and a one-hot query reads it back. Every row becomes a memory cell, and cartridge, RAM and registers all live in those rows. The resulting checkpoint is an ordinary Hugging Face folder of 466.6M bf16 parameters (933 MB) — but only 9.3M are nonzero, so it zips to 3.3 MB — comprising seven DeltaNet layers holding the circuit and one all-zero attention layer that HF's cache machinery requires. A host program (nesformer/host.py) supplies everything the model does not: a scanline PPU, controllers, and NMI injection at vblank.

The execution model is a token stream, not a program. Each instruction emits a record whose final token commits it; the PC is implied rather than written, reconstructed as a jump target plus three DeltaNet counters tallying instruction lengths since the last branch. Most instructions cost one token; real game code averages 1.1–1.3. Correctness was established the hard way: the reference CPU matches nestest's golden log for 3,348 instructions and py65 across 5.7 million instructions; the compiled circuit predicts every reference token; and free-running weights reproduce identical traces for Thwaite (1.9M tokens, 600 frames) and Doug Fraker's Full Game (2.6M tokens, 420 frames), with all saved frames bit-identical to a conventional emulator. The catch is speed — roughly 1,650 tokens/s on the numba engine, 210 on numpy, 10 in stock transformers, against the ~700,000 tokens/s a real console demands. An idle-loop detector that skips repeated vblank waits recovers 2.6–4.2×, leaving the whole thing 150–290× slower than original hardware.

"Nobody trained these weights; a compiler computed every one" — and because the 466.6M-parameter Qwen3.5 checkpoint is 98% zeros, the "Nintendo" compresses to a 3.3 MB file that still predicts every 6502 token exactly, matching a reference emulator frame-for-frame while running 150–290× slower than the real console.

Key Highlights
  • No training involved: every weight is computed by a compiler (Qwenputer's chipformer), producing a standard Qwen3_5ForCausalLM checkpoint that loads with from_pretrained and needs no custom code.
  • Gated DeltaNet state matrices double as addressable memory — one-hot key/query pairs turn each 128×128 head state into rows of RAM, registers and cartridge ROM.
  • The PC is never stored; it is reconstructed from jump targets plus three per-length instruction counters, letting most instructions commit in a single token at 1.1–1.3 tokens per instruction in real game code.
  • Verification is unusually rigorous: nestest's golden log, 5.7M instructions against py65, teacher-forced checks over 700k+ tokens, and free-running traces whose rendered frames all match a reference emulator exactly.
  • Hard limits: NROM (mapper 0) only, official opcodes only, no IRQs, no sound, and a host-side PPU that renders per-scanline — with throughput of ~1,650 tokens/s against the ~700k/s a real NES needs.

Cisco gives engineer unlimited AI tokens to rewrite legacy code
⬆ 230 pts 💬 281 HN comments

Cisco president and chief product officer Jeetu Patel has handed one of the largest refactoring efforts in enterprise networking to a 27-year-old engineer, Padmanabhan "Paddy" Krishnamurthy, who joined via Cisco's 2025 acquisition of the real-time translation startup EzDubs. Krishnamurthy's mandate: use unlimited AI token budget to refactor 98% of Cisco's legacy code within 24 months, with a four-week prototype deadline to prove a two-person team can do it. The technical premise is that translating an existing, behaviorally-specified system from one implementation into another — with the old code as an executable oracle — is precisely the class of task LLMs perform well, unlike greenfield design or novel architecture. Patel frames the hire as a deliberate inversion of seniority: fresh hires ask questions veterans have stopped asking, and the friction between them is generative rather than dysfunctional.

The story resonated on HN because it touches several live nerves at once: the collapse of entry-level hiring, the reliability of large-scale AI-driven rewrites of systems nobody fully understands, and Cisco's long record of CVEs, hardcoded credentials and device firmware that ships in a fragile steady state. Commenters largely accepted the narrow technical thesis — mechanical translation is a good fit for AI, especially if a comprehensive test harness is built first — while rejecting the surrounding narrative. The recurring objections were semantic, not syntactic: whether an agent can preserve undocumented behavior, accumulated bug fixes, protocol quirks and inter-vendor interop edge cases that decades of trial-by-fire encoded. Multiple practitioners offered counter-anecdotes of successful legacy migrations (a FoxPro app reverse-engineered in a week, a 20-year embedded system rewritten in three months for roughly $20k in tokens), and equally sharp warnings about translated code producing new classes of bugs — one commenter cited a runtime silently going from single-threaded to multithreaded — and of test suites nobody actually reads.

"I've given him unlimited tokens because he's going to refactor code. So I'm like, you can go, you can go nuts" — a two-person team, 98% of Cisco's legacy code, 24 months.

Key Highlights
  • Cisco's Jeetu Patel gave a 27-year-old ex-founder unlimited AI tokens to refactor 98% of legacy code within 24 months, starting with a four-week proof of concept.
  • Commenters agree language/platform translation with the old code as an oracle is a genuine LLM strength — provided a comprehensive test suite exists first.
  • Core objection is semantic preservation: undocumented behavior, accumulated bug fixes and protocol interop quirks that only greybeards remember.
  • Several engineers shared real migration wins (FoxPro reverse-engineering, a 20-year embedded rewrite for ~$20k in tokens) alongside warnings about silently changed runtime semantics.
  • Cisco's CVE history and firmware quality undercut both the urgency framing and the fear that AI could make the product meaningfully worse.

Backdoor in Claude Code for VS Code extension on the Cursor Marketplace
⬆ 930 pts 💬 537 HN comments

Phorion's advisory describes a supply-chain compromise of the Claude Code for VS Code extension bundle as distributed through the Cursor Marketplace, where an injected IIFE was prepended to the minified extension.js. Because VS Code-family extensions run with the IDE's and user's privileges, the payload fires on module load—before the normal activate callback—giving immediate access to local files, source code, and developer tooling without any user interaction. Versions 2.1.312 and 2.1.313 were affected. The implant plants an attacker-controlled Ed25519 key (comment svc-telemetry) in ~/.ssh/authorized_keys, then opens a reverse SSH tunnel to 134.209.82.225 as user tunnel using a second embedded key (svc-telemetry-tun) with -R *:0:localhost:22 and -N, so an operator can later connect through the allocated server port to the victim's local sshd and obtain an interactive shell. Persistence arrives as a user LaunchAgent masquerading as com.apple.sysmond.plist executing ~/.config/.smt, a Linux @reboot cron entry, or a Windows SysMon scheduled task with a Startup-folder fallback.

The operation is notably sloppy in ways that shape the risk calculus. On macOS, systemsetup -getremotelogin is invoked without elevation; it prints an administrator-access error and exits 0, so the /Off/i test fails and the sudo -n enablement step never runs—meaning an inbound path exists only if Remote Login was already on. The Windows path pipes PowerShell through a helper hardcoding /bin/sh, and the Linux crontab check can wipe existing user jobs. Recon is limited to a single beacon POSTed to 134.209.82.225:8099/beacon (and inexplicably 127.0.0.1:8099) carrying hostname, OS, Git email, public IP, stage status, and up to 40 environment variable names matching /KEY|TOKEN|SECRET|PASS|AWS|GCP/i—an inventory, not exfiltration. Anthropic's felixrieseberg and ddworken insist no Anthropic system was compromised; Cursor's notice says the malicious build was live roughly 2:27 a.m. to 1:35 p.m. PT. Uninstalling the extension removes nothing: keys, LaunchAgents, and detached tunnel loops must be cleaned explicitly.

The malware's own bug—treating "you need administrator access to run this tool" as "SSH is already on"—means macOS hosts without Remote Login enabled never had a working inbound path, even though the authorized_keys backdoor and LaunchAgent persistence were still dropped.

Key Highlights
  • A tampered build of the Claude Code extension (2.1.312/2.1.313) was published to the Cursor Marketplace and removed after roughly 11 hours live, per Cursor's notice.
  • An IIFE injected ahead of the minified extension.js runs on module load, planting an Ed25519 key in ~/.ssh/authorized_keys and establishing a detached reverse SSH tunnel with -R *:0:localhost:22.
  • Persistence uses a user LaunchAgent disguised as com.apple.sysmond.plist executing ~/.config/.smt, an @reboot cron entry, and a SysMon scheduled task on Windows.
  • A macOS privilege bug in the systemsetup -getremotelogin check means SSH enablement often silently fails, while the beacon and persistence still land.
  • Remediation requires killing tunnel processes, unloading the LaunchAgent, deleting /tmp/.stk_* and ~/.config/.smt*, and rotating any credentials whose variable names matched the KEY|TOKEN|SECRET filter.

#2
The $6.3B Binance hack was pulled off in just 20 minutes
⬆ 507 pts 💬 357 HN comments

Binance lost roughly $6.3 billion in crypto across at least ten blockchains—Ethereum, Bitcoin, Tron, Solana among them—in a drain that TRM Labs says took about 20 minutes on October 29, though preparation began at least 36 hours earlier. The attack chain is unusually well-documented for a heist of this scale: the operator ran three small test withdrawals, deployed a first code payload against two wallets, rehearsed the final version on a third and routed the test funds back to itself, then four hours later installed the same code onto a Binance hot wallet. Binance's initial statement pointed at a compromised DevOps engineer's laptop granting access to a service container that could submit withdrawals; a later statement from Richard Teng conceded the attacker 'did not simply use one engineer's permissions.' TRM Labs and Chainalysis both attribute the operation to TraderTraitor, the North Korean unit the FBI tied to last year's $1.5B Bybit theft, citing commingling of Binance funds with proceeds from the Bitget exploit.

The economics of freezing explain why this is different from a conventional breach. Roughly $2.8 billion—about 44 percent—has been frozen, and nearly all of it is stablecoins, where issuers can blacklist addresses unilaterally. The residual $3.3 billion is Bitcoin, Ether and XRP, which Elliptic's Tom Robinson notes 'no one can freeze'; it can only be interdicted when it touches a regulated venue. Chainalysis reports laundering patterns 'we have not seen before,' with thousands of transactions processed fast enough to imply automation deliberately obscuring the trail. If attribution holds, a single theft nearly doubles North Korea's cumulative crypto haul. Meanwhile Binance, which claims $155B in assets and $14B daily volume, says it will absorb all losses—a solvent-exchange posture that itself papers over the operational question of why so much sat in internet-connected hot wallets, reachable by one identity's credentials, with no evident withdrawal velocity control.

About 44 percent of the $6.3B was frozen—almost entirely stablecoins—leaving $3.3B in Bitcoin, Ether and XRP that Tom Robinson says 'no one can freeze.'

Key Highlights
  • $6.3B drained across 10+ blockchains in ~20 minutes, after 36+ hours of testing and rehearsal on live Binance wallets
  • Initial vector: compromised DevOps engineer's laptop with access to a service container that could submit withdrawals; Binance later said more than one set of permissions was involved
  • TRM Labs and Chainalysis attribute to TraderTraitor (North Korea), based on on-chain commingling with Bitget exploit funds and Tornado Cash funding
  • ~$2.8B frozen, nearly all stablecoins; $3.3B in BTC/ETH/XRP is unfreezable and only interceptable at exchange ingress
  • Chainalysis observes novel laundering patterns and automation across thousands of rapid transactions

Northflank Breached
⬆ 456 pts 💬 331 HN comments

Northflank, a UK-founded PaaS that markets itself as the runtime for autonomous software and secure sandbox execution, published an escalating series of status-page updates confirming a security incident that forced it to assume total compromise of customer secrets. The timeline is unusually compressed: a Wiz threat alert fired at 11:43 UTC, Northflank engineers reviewed it a minute later, an initial network policy patch landed at 12:02, additional patches at 12:50 and 13:05, and Wiz CIRT support was requested at 13:00 — roughly twenty minutes of detection-to-containment. The public guidance, however, was maximally conservative: 'assume all environment variables have been decrypted and begin rotation immediately,' covering workload secrets, secret groups, and global secrets, plus disabling public expose on addons. Seven platform components — networking, certificates, services, addons, jobs, builds, logs and metrics — went to major outage, while the control-plane app, API, marketing site, and docs stayed up, suggesting the blast radius was the multi-tenant data plane rather than the front end.

The most damaging follow-up was user-reported abuse of AI provider API keys stored in Northflank, with the company noting 'similar IP addresses are contained in' Wiz's 'Black October' report — implicitly linking the intrusion to a broader credential-harvesting campaign against AI infrastructure. Northflank then enabled audit logs for all tiers, including free users, and progressively unlocked self-service secret rotation for Postgres and MongoDB (3:12 PM UTC) and MySQL and Redis (1:34 PM UTC the next day), a release-velocity signal that rotation tooling simply did not exist for most backends beforehand. HN's read is that this is not an isolated incident but the sixth near-identical breach of a modern multi-tenant as-a-service vendor since September, alongside PingCAP/TiDB, Fireworks AI, Zeabur, OpenCode Console, and Railway. The structural problem identified is architectural: PaaS dashboards are expected to display env vars back to users and agents, which makes credential plaintext a first-class read surface for any attacker who reaches the control plane.

'Assume all environment variables have been decrypted. Disable/rotate all keys.' — Northflank's own incident guidance, which effectively told every customer that the entire value proposition of a managed secrets store had failed at once.

Key Highlights
  • Northflank instructed all customers to assume every environment variable — workload secrets, secret groups, and global secrets — was decrypted, and to rotate everything immediately.
  • Attack timeline was extremely fast: Wiz alert at 11:43 UTC to first network policy patch at 12:02, with Wiz CIRT engaged by 13:00 and multiple patches inside 90 minutes.
  • Users reported unauthorized use of AI provider API keys stored in Northflank; the company linked similar source IPs to Wiz's 'Black October' credential-theft campaign.
  • Audit logging was a paid-tier feature until the incident, when Northflank enabled it for all customers including free users — widely criticized as a monetization-of-basics failure.
  • Commenters count six comparable multi-tenant breaches since September (PingCAP/TiDB, Fireworks AI, Zeabur, OpenCode Console, Railway, Northflank), framing it as a systemic PaaS security crisis.

#5
Florilegium: Procedural Flowers in LaTeX
⬆ 328 pts 💬 49 HN comments

Florilegium, by Kevin Raymond, draws Delft-blue floral page margins straight into PDF path operators from Lua during a single LuaLaTeX pass — no images, no imported paths, no external assets. Every petal, leaf, tendril and snail is a parametric construction: tapered strokes are pairs of offset Béziers rather than sampled ribbons, and each motif is painted the way a watercolorist would — a flat wash, darker blotches multiplied over it, pigment pooled at the edges, white streaks lifted out, fine veins, almost no outlines. Composition comes in two modes. The authored variant plants three stems through hand-picked control points so every flower traces back to a root; the grown variant sways stems up the column as smooth noise of their height, then runs a greedy loop that repeatedly finds the largest free disc within reach of a stem, selects a motif sized to fit, and grows a tangential branch to it — explicitly credited to Wong, Zongker & Salesin's 1998 SIGGRAPH paper, Computer-Generated Floral Ornament.

The remaining engineering is what earns the repository its 328 points. Palette ramps interpolate in OKLCH from a single ink color so the palest wash stays blue instead of going gray; themes swap primitives without the growth loop ever knowing what it draws — theme=math cascades Apollonian gaskets, Koch snowflakes and Vogel's disc down the margin, joined by copper arrows. Density and intensity dials degrade gracefully from a full garden to a single vine. A complete PostScript port reimplements Lua closures as procedures built at run time, captures fills per layer via pathforall, and fakes transparency via -dALLOWPSTRANSPARENCY or color-mixing, rendering two pages in roughly 2.5 seconds. The README — and by the author's admission much of the code — was written with Claude, which became the thread's chief friction: "Gorgeous but the AI text is so grating," "It's so recognizable lol. All the staccato."

"No images, no imported paths, no external assets" — every flower is computed in Lua and written as PDF path operators while the page is typeset, so each seed yields a different garden and, via the PostScript port, each physical print run takes its seed from the clock.

Key Highlights
  • All geometry is computed in Lua and emitted as literal PDF path operators in one node per page; TeX performs no arithmetic
  • Grown composition implements a greedy largest-free-disc space-filling loop credited to Wong, Zongker & Salesin, SIGGRAPH 1998
