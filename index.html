VS Code inserting 'Co-Authored-by Copilot' into commits regardless of usage
⬆ 1162 pts 💬 585 HN comments

A now-merged pull request (#310226) in the VS Code repository changed the default value of the `git.addAICoAuthor` setting from 'off' to 'all', causing the IDE to automatically insert a 'Co-authored-by: Copilot <copilot@github.com>' trailer into every Git commit, regardless of whether Copilot was actually used. The change was made by a product manager with minimal description and reviewed only by a single developer. Ironcially, Copilot's own AI review flagged a fallback inconsistency: the runtime code still used 'off' as the fallback, while the schema default was 'all'. Despite this warning, the PR was approved and merged. The feature was later changed to 'chatAndAgent' and then reverted to 'off' after widespread backlash, but the damage to user trust was immediate.

The community response was swift and furious. Users reported the unwanted tag appearing even when AI features were explicitly disabled (`chat.disableAIFeatures: true`). One developer likened it to 'vandalism' and noted that 'Co-authored-by: Copilot' never appears in the commit message UI—it is added silently. The PR received 372 downvote reactions and hundreds of angry comments. Microsoft's dmitriv publicly apologized: 'There was no ill intent by evil corporation, but rather a desire to support functionality that some customers expect.' The incident has been compared to the 'Sent from my iPhone' marketing tactic, but with far greater consequences—Git commits serve as legal and technical records, and falsifying authorship could have copyright implications. Many users are now exploring alternatives like Zed, NeoVim, or Cursor, citing a fundamental breach of trust.

Copilot's own AI review warned that the change created a fallback inconsistency and could lead to unexpected behavior, yet the warning was ignored and the PR was merged anyway.

Key Highlights
  • PR #310226 changed the default of `git.addAICoAuthor` from 'off' to 'all', silently adding 'Co-authored-by: Copilot' to all commits.
  • Copilot's AI review flagged a fallback mismatch in the code, but the PR was merged over that objection.
  • Users reported the tag appearing even when AI features were disabled, causing confusion and anger.
  • Microsoft quickly reverted to 'off' and apologized, but trust was damaged and calls to switch IDEs grew.
  • The incident highlights a broader pattern of companies injecting AI branding into user outputs without consent.

The agent harness belongs outside the sandbox
⬆ 102 pts 💬 77 HN comments

The article argues that the agent harness—the loop driving an LLM—should run outside the sandbox where the agent executes tools. This architecture keeps credentials out of the sandbox, allows suspending sandboxes when idle, and treats sandboxes as cattle that can be replaced mid-session without losing state. The author, Andrea Luzzardi, from Mendral (a CI failure diagnosis agent), highlights that multi-user scenarios surface problems single-user designs don't, such as shared skills and memories across sessions. Key challenges include durable execution (solved via Inngest), sandbox lifecycle with sub-second resume (using Blaxel at 25ms), and virtualizing filesystem access so that path-based tools like read/write route to either the sandbox (for workspace files) or a database (for skills/memories). The article emphasizes keeping the tool API identical to what models were trained on (e.g., Claude Code's interface) to avoid diluting model performance.

The post details three critical solutions: durable execution via checkpointed steps (Inngest), sandbox suspension with 25ms resume (Blaxel), and a virtualized filesystem that intercepts reads/writes to special paths like /skills/ and /memory/ and routes them to a database. This avoids building a distributed filesystem for multi-user consistency. However, the author admits gaps: bash commands can bypass virtualization, and the dependency on Claude Code's evolving layout is a risk. The community reaction is mixed: many commenters (e.g., zmmmmm, tptacek) question the security model, arguing the harness itself must be trusted and sandboxed, while others debate definitional clarity of 'harness.' The article also reveals a broader trend: as models improve, agent architectures are rapidly iterating—Manus rebuilt its harness five times in six months, and Anthropic itself changes Claude Code's harness with model updates. The piece is essential reading for engineers building multi-user agents, but its security assumptions remain contentious.

25ms resume from standby is low enough that the agent can't tell the sandbox was ever gone.

Key Highlights
  • Agent harness (the loop driving LLM) should run outside the sandbox for security and resource efficiency.
  • Outside model keeps credentials out of sandbox, allows suspending sandboxes when idle, and makes sandboxes replaceable cattle.
  • Durable execution via Inngest ensures agent sessions survive deploys and failures.
  • Sandbox lifecycle uses 25ms resume from standby using Blaxel.
  • Virtualized filesystem routes workspace paths to sandbox, skill/memory paths to database, keeping model-trained API surface unchanged.

A physics engine with incremental rollback for multiplayer games
⬆ 85 pts 💬 28 HN comments

Easel, a multiplayer game engine, has developed a custom physics engine featuring incremental rollback to support large worlds. Traditional rollback netcode requires snapshotting the entire physics state every frame, which becomes prohibitively expensive for worlds with thousands of static objects. By leveraging sleep mechanics that put bodies to sleep immediately when forces are balanced, and a BVH spatial index that performs lazy, incremental rebalancing, Easel only snapshots and rolls back the handful of objects that change per frame (often fewer than 30). This 30-50x reduction in snapshotting overhead makes games with large, mostly-static environments—like a spaceship in Among Us—feasible. The engine also introduces a non-bouncy stepping mechanism via ForcefulStep, integrated into position correction to avoid the common issues of velocity damping or kinematic overrides.

The engine’s continuous collision detection (CCD) avoids pitfalls seen in other engines: Rapier’s early position integration can mis-sweep when bodies initially touch a mirror, while Box2D 3.0 drops dynamic-to-dynamic CCD entirely. Easel solves CCD after resolving collisions, ensuring correct time-of-impact sweeps. Photon Quantum, a professional rollback netcode engine, lacks CCD due to its stateless design. Additionally, bodies without colliders now move under velocity/turnRate, addressing a game-dev pain point. The engine is built on Parry’s collision algorithms (used in Rapier). Commenters praised the idea—gafferongames called it “cool”—and discussed delta compression (stephc_int13), deterministic physics for decentralized verification (ornitorrincos), and open-sourcing (maxbendick).
