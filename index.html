MiMo-v2.5-Pro-UltraSpeed: 1T model with 1000 tokens per second
⬆ 580 pts 💬 426 HN comments

Xiaomi's MiMo-V2.5-Pro-UltraSpeed achieves 1000 tokens per second inference on a 1-trillion-parameter MoE model using a single 8-GPU commodity node, a feat previously requiring specialized hardware like Cerebras or Groq. The breakthrough stems from extreme model-system codesign between Xiaomi's model team and the TileRT systems team. On the model side, FP4 quantization (MXFP4) is applied selectively to MoE experts, reducing memory bandwidth pressure while preserving reasoning quality via quantization-aware training. Combined with DFlash—a block-level masked parallel speculative decoding method that attains acceptance lengths of 6.3 tokens in coding scenarios—the model dramatically reduces per-token latency. On the system side, TileRT introduces a persistent engine kernel, warp specialization, and hardware-software co-optimization to eliminate microsecond-scale execution gaps between operators, enabling continuous data flow and compute overlap.

The result is a 3× price premium over the base MiMo-V2.5-Pro but delivers 10× speed, making it competitive for real-time applications like coding agents, high-frequency trading, and medical imaging. The API is offered on a limited-time, application-based basis (June 9–23, 2026), reflecting constrained high-speed inference resources. Commenters highlight the paradigm shift: speed enables parallel reasoning paths (Best-of-N, tree search) within the same wall-clock time, transforming AI from a tool one waits on to an extension of thought. However, skeptics note potential quality degradation despite claims of lossless quantization, and some users report mixed coding performance. The open-source release of FP4-DFlash checkpoints on HuggingFace invites community experimentation, while the broader context includes geopolitical GPU restrictions and competitive pricing from Chinese providers against rising US model costs.

#11
FrontierCode
⬆ 203 pts 💬 35 HN comments

FrontierCode, a new benchmark from Cognition AI, shifts the focus from code correctness to code quality by measuring whether AI-generated code would actually be merged into production repositories. Unlike existing benchmarks like SWE-Bench, which primarily test functional correctness, FrontierCode evaluates mergeability through a multifaceted rubric including behavioral correctness, test quality, scope discipline, style, and adherence to codebase standards. The benchmark was crafted by 20+ open-source maintainers who spent over 40 hours per task to define realistic, challenging tasks from their own repos, and employ novel grading methods like reverse-classical tests, scope constraints, and adaptive classical grading to minimize false positives and negatives. The result is a rigorous evaluation that, according to the authors, achieves an 81% lower false positive rate than SWE-Bench Pro.

Results from FrontierCode's three difficulty tiers (Extended, Main, Diamond) reveal that even the most capable models struggle on this new standard. The top performer, Claude Opus 4.8, scored only 13.4% on the 50-hardest-task Diamond set, while GPT-5.5 managed 6.3% but used up to 4x fewer tokens. Open-source models like Kimi K2.6 performed significantly worse, with 3.8% on Diamond. The benchmark's design intentionally avoids overspecified prompts; tasks are concise and require agents to infer maintainer intent. This emphasis on quality over mere correctness addresses a critical gap in AI coding evaluation, as highlighted by Cognition's assertion that 'correctness is now table stakes.' The release of FrontierCode signals a maturation in how the industry assesses AI's readiness for production code.

The best performing model, Claude Opus 4.8, achieves a score of only 13.4% on FrontierCode Diamond, highlighting the vast gap between current AI capabilities and real-world code quality standards.

Key Highlights
  • FrontierCode measures code mergeability via rubric graded by open-source maintainers, not just functional correctness.
  • Novel grading methods include reverse-classical tests, scope constraints, and adaptive classical grading to reduce misclassification.
  • Top model Claude Opus 4.8 scores 13.4% on the hardest Diamond subset, indicating unsaturated benchmark.
  • GPT-5.5 achieves lower scores but with significantly better token efficiency (4x fewer tokens than Opus 4.8).
  • 20+ maintainers invested 40+ hours per task, and the benchmark achieves an 81% lower false positive rate than SWE-Bench Pro.
