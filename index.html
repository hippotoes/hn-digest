The vulnerability stems from an incomplete fix where the gateway RPC path was hardened, but the plugin command path omitted scope validation, enabling privilege escalation under specific conditions. This vulnerability exemplifies broader challenges in securing democratized technology, where user ignorance and poor defaults amplify threats, prompting calls for sandboxing and formal verification in critical systems.

SSH certificates: the better SSH experience
⬆ 241 pts 💬 103 HN comments

The article delves into SSH certificates as a superior alternative to traditional SSH key-based authentication, addressing long-standing issues like Trust on First Use (TOFU) and host key management. SSH certificates leverage an SSH Certification Authority (CA) to sign both user and host keys, eliminating the need for manual public key distribution and the 'known_hosts' file clutter. This approach, based on OpenSSH's format since version 5.4, simplifies security by embedding metadata such as principals, validity periods, and access restrictions directly into certificates, thereby enhancing control and reducing operational overhead in multi-server environments.

Implementation involves creating an SSH CA key pair, signing public keys with options like expiration dates, forced commands, and source IP limitations, then configuring servers to trust the CA and clients to recognize certified hosts. Key advantages include no TOFU prompts, automatic expiration for credentials, and centralized revocation through CA management. However, the setup requires careful orchestration, with steps like configuring 'TrustedUserCAKeys' and 'HostCertificate' directives. Societally, this shift empowers organizations to enforce least-privilege access, mitigate lateral movement risks in networks, and streamline compliance in enterprise settings, though it introduces dependencies on CA availability and proper key lifecycle management.

SSH certificates eliminate the need for Trust on First Use and host key warnings, allowing centralized management with automatic expiration and fine-grained access controls.

Key Highlights
  • SSH certificates replace traditional SSH keys and TOFU with a CA-based model for enhanced security and management.
  • Certificates include metadata such as principals, validity periods, forced commands, and source IP restrictions.
  • Setup involves creating an SSH CA, signing user and host keys, and configuring clients and servers with trust lines.
  • Advantages include no host key warnings, automatic expiration, and centralized access control without public key distribution.
  • Challenges include CA dependency, revocation management, and initial configuration complexity in production environments.

⬆ 158 pts 💬 20 HN comments

TinyGo represents a significant evolution in the Go ecosystem by leveraging LLVM to compile Go code for embedded systems and WebAssembly, targeting resource-constrained environments where standard Go's runtime and binary size are prohibitive. This compiler adapts Go's garbage-collected, concurrent model to microcontrollers with limited memory and processing power, such as the BBC micro:bit and Arduino Uno, while also generating compact WASM output for web and edge computing via WASI. The technical foundation lies in optimizing LLVM's intermediate representation to strip unnecessary features, balancing Go's expressive power with the austere requirements of embedded hardware and the security sandbox of WebAssembly, thereby bridging high-level programming with low-level execution contexts.

Data points from the community highlight both adoption and limitations: for instance, users report build times of ~1 second for TinyGo versus standard Go, and successful implementations like ServiceRadar using TinyGo with Wazero for WASM plugins. However, comments reveal gaps in stdlib support, such as missing networking in WASI and panicking stubs for crypto modules, which constrain use cases like compiling Tailscale for OpenWRT routers. Specific examples include streaming RTSP feeds through WASM, demonstrating real-world utility, yet debates persist on real-time performance due to GC overhead, with suggestions to disable GC for deterministic behavior. Societally, TinyGo democratizes embedded and web development by extending Go's simplicity to new domains, though it challenges traditional expectations of language completeness in specialized compilers.

TinyGo can produce WebAssembly code that is very compact in size, enabling efficient execution in browsers and server environments supporting WASI, while compiling for over 100 microcontroller boards from maker to industrial scales.
