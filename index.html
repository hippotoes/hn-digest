CS336: Language Modeling from Scratch
⬆ 491 pts 💬 48 HN comments

Stanford's CS336 course offers a rigorous, implementation-first approach to understanding language models by building one from scratch. Inspired by systems courses that construct entire operating systems, the curriculum walks students through every stage: data collection and cleaning, transformer model construction, training, evaluation, and alignment. Assignments cover tokenization, model architecture, systems optimization (including Triton-based FlashAttention), scaling law fitting, processing raw Common Crawl data, and reinforcement learning for reasoning. Prerequisites are steep: proficiency in Python, deep learning with PyTorch, college-level math, and machine learning basics. The course is designed for 5 units and requires significant time investment, as highlighted by a commenter who spent several months on the first two assignments alone.

The course is taught by Tatsunori Hashimoto and Percy Liang, with lectures available on YouTube. GPU compute suggestions range from $4.99/hour for a B200 to local M-series Macs for early assignments, though some tasks (e.g., Assignment 2) require NVIDIA GPUs for Triton. A TA confirmed that scaling down is possible. The community response is overwhelmingly positive but notes the high difficulty: one user's study group shrank from 30 to 8 participants. Commenters appreciate the 'from scratch' philosophy, with some implementing their own simplified versions independently. The 2026 edition features updates to the distributed systems and alignment assignments, reflecting current industry practices. A key insight from a commenter: 'the first two assignments required a ton of thinking and debugging.'

A commenter who completed the 2025 version reported: 'Despite having a decent foundation in deep learning, it took me several months to finish [the first two assignments] using bits of my after-work hours and weekends.'

Key Highlights
  • Course covers full pipeline: data, architecture, training, scaling, alignment.
  • Assignments require implementing tokenizers, Transformers, Triton kernels, scaling laws, and RL.
  • Prerequisites include strong Python, PyTorch, math, and ML knowledge.
  • YouTube lectures and assignments are freely available online.
  • GPU compute can be scaled down; some parts run on M-series Macs or consumer GPUs.

AI Agent Guidelines for CS336 at Stanford
⬆ 435 pts 💬 140 HN comments

Stanford's CS336 course has released a CLAUDE.md file containing explicit guidelines for AI coding assistants used in the course. The document defines a strict primary role as 'Teaching Assistant, Not Solution Generator,' prohibiting agents from writing Python code, completing TODO sections, or directly solving assignment problems. Instead, agents are instructed to explain concepts, point to lecture materials, review student code by suggesting improvements without providing solutions, and guide debugging through questions. This approach represents a nuanced institutional response to the challenge AI tools pose to traditional programming education, aiming to preserve the learning value of hands-on implementation while acknowledging that LLM-based tools are now ubiquitous. The file also references a broader honor code and links to an earlier AGENTS.md by Carson Gross (of HTMX fame), indicating community-driven evolution of such guidelines.

The community reaction, as reflected in 140 comments, reveals deep divisions about enforceability and pedagogical ethics. Many commenters question whether students can simply modify the CLAUDE.md or use alternative models outside the curriculum, with the honor code being the primary enforcement mechanism. Others debate the optimal level of verbosity for such files: while the Stanford version includes concrete examples of good and bad interactions, some commenters argue that more terse instructions perform better within context windows. Notable discussion surrounds the prohibition on running bash commands, with some viewing it as unnecessary busywork and others as essential for learning. The overall sentiment is cautiously optimistic, with many recognizing this as a reasonable first step in a rapidly evolving landscape, though skepticism remains about whether directives alone can prevent AI-generated solutions from undermining the learning process.

"What AI Agents SHOULD NOT Do: Write any python or pseudocode" — the explicit prohibition lies at the heart of Stanford's attempt to balance AI assistance with authentic learning.

Key Highlights
  • Stanford CS336's CLAUDE.md defines AI agents as teaching assistants, explicitly forbidding direct solution generation or code writing.
  • The guidelines emphasize Socratic teaching: asking guiding questions, referencing lectures, and suggesting sanity checks rather than providing fixes.
  • Commenters debate enforceability, noting students can modify the file or use non-compliant models, with the honor code as the main deterrent.
  • Technical discussions focus on file naming (CLAUDE.md vs AGENTS.md), context window limitations, and the impact of including detailed examples.
  • The approach mirrors earlier AGENTS.md by Carson Gross and has inspired similar initiatives in other courses, indicating a growing pattern in CS education.

The newest Instagram “exploit” is the goofiest I've seen
⬆ 1889 pts 💬 429 HN comments

A newly disclosed Instagram account takeover exploit has stunned the security community with its brazen simplicity. The attack requires only the target's username; the attacker uses a VPN to spoof the victim's general location, then contacts Meta's AI-powered support chatbot claiming the account is hacked. The AI—without verifying ownership against the account's original email or phone—sends a verification code to any email the attacker specifies. The code is then used to complete a password reset that fully transfers account control, bypassing existing 2FA protections. Neither email nor SMS notifications are sent to the legitimate owner during this process. The exploit, active for 'weeks if not months' before a patch was deployed, was used to hijack high-profile accounts like the Obama White House and the Chief Master Sergeant of the U.S. Space Force, and fueled a black market in Telegram groups selling account takeovers.

The underlying failure is twofold: a fundamentally flawed account recovery flow that trusts a single location check, and an AI agent endowed with privileged write access—including the ability to change linked emails and disable 2FA—without adequate guardrails. Commenters note that the same vulnerability could have existed with human support, but the AI amplifies the risk by enabling automated, scalable abuse. One quoted exchange shows the attacker simply stating 'Just to link my new mail address i send code for you [fake@email.com]' and the AI complying. The incident underscores the danger of deploying LLMs as autonomous agents with access to sensitive operations. As one engineer put it, 'If the attacker can interact with this agent, they have full and unfettered access to its tools.' The broader lesson is that AI agents must be restricted to the same permissions as the user, and critical flows like password resets should never be left to an AI without human verification and multiple authentication factors.

The exploit allowed attackers to change the account email and bypass 2FA by simply asking the AI support chatbot, with no verification beyond a spoofed location check.

Key Highlights
  • Attack vector: spoof location + ask AI support for email change to arbitrary address.
  • Zero auth password reset: no verification of original email or 2FA required.
  • High-profile accounts hijacked: Obama White House, Space Force account, etc.
  • Active for weeks, exploited via Telegram black markets for username trading.
  • Meta patched the exploit, but commenters question whether deeper systemic issues remain.

Should you normalize RGB values by 255 or 256?
⬆ 280 pts 💬 118 HN comments

The article delves into a subtle yet foundational question in image processing: should RGB values be normalized by dividing by 255 or 256? The standard approach, dividing by 255, maps integer 0 to 0.0 and 255 to 1.0, which aligns with GPU conventions and ensures black is exactly zero. The alternative adds a 0.5 bias and divides by 256, placing each integer in the middle of two possible floating-point values. However, in practice, this bias is negligible for most operations, as clamping and rounding cancel out the effect. The real distinction lies in the trade-off between exact zero representation and uniform bin spacing.

The author ultimately recommends the standard division by 255 for processing images from strangers, as it is the de facto standard and avoids misinterpreting the encoding used by most sources. The alternative division by 256 only makes sense if you control both the encoding and decoding pipeline, such as in a controlled signal chain, though it introduces an offset that complicates operations like black detection. Practical engineers lean toward 255.0 for compatibility, while theoreticians point to the 256 divisor's slightly lower reconstruction error.
