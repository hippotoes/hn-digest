Multi-Stream LLMs: new paper on parallelizing/separating prompts, thinking, I/O
⬆ 112 pts 💬 12 HN comments

This paper proposes a fundamental architectural shift for LLMs: replacing the traditional single-stream chat format with multiple parallel streams dedicated to distinct roles—thinking, user input, system instructions, and tool outputs. In current agents, the model must serially process messages, creating bottlenecks: it cannot generate output while reading input, cannot react while writing, and cannot think while acting. The authors introduce Multi-Stream LLMs, where each forward pass simultaneously reads from several input streams and generates tokens across multiple output streams, all causally dependent on earlier timesteps. This data-driven change is realized through instruction-tuning on parallel stream formats. The approach promises improved efficiency via parallelism, better security through separation of concerns, and enhanced monitorability. However, the paper acknowledges that their models are small-scale and trained on limited data, leaving large-scale validation to future work.

The Hacker News reaction is cautiously optimistic, with engineering-oriented debates surfacing. Enthusiasts like killcoder compare the approach to familiar asynchronous patterns in software engineering, noting that tool calling and code generation are naturally parallelizable. jhack highlights the paper's own caveat about scale, suggesting that larger models could unlock these benefits. Conversely, bob1029 reports a first-hand experience where disabling parallel tool calls in his gpt5.4 harness improved quality, arguing that serial execution remains more predictable. Technical questions emerge around handling contradictory tokens across streams and merging representations—points raised by coaliteddy and zozbot234. Practical concerns about context splitting and attention budgets also appear, reflecting the community's deep engagement with the architecture. The paper's core insight—breaking the 'cannot act while reading' bottleneck—resonates with many, but the path to production remains uncertain.

The agent cannot act (generate output) while reading, and in reverse, cannot react to new information while writing.

Key Highlights
  • Proposes replacing single-stream chat with multiple parallel streams for thinking, input, output, and tool use.
  • Each forward pass reads from multiple input streams and generates tokens in multiple output streams simultaneously.
  • Claims benefits in efficiency, security (by stream isolation), and monitorability.
  • Training done via instruction-tuning on small-scale models, requiring larger validation.
  • Comments reveal excitement about async patterns, but also concerns about quality, merging consistency, and context splitting.
