#5
Interaction Models
⬆ 223 pts 💬 26 HN comments

Thinking Machines Lab’s research preview of “interaction models” proposes a paradigm shift in human-AI collaboration: instead of bolting interactivity onto turn-based models via external scaffolding (e.g., voice-activity detection), they train a unified model from scratch that natively handles continuous, real-time bidirectional exchange across audio, video, and text. The core architectural innovation is time-aligned micro-turns—processing 200ms chunks of input while simultaneously generating 200ms chunks of output, eliminating artificial turn boundaries. This enables the model to perceive silence, overlap, and interruption as part of its context. The system uses encoder-free early fusion (lightweight embeddings for audio dMel features and 40x40 image patches) and co-trains all components (transformer, audio decoder with flow matching) end-to-end. To meet strict latency requirements, they optimized inference with persistent streaming sessions in GPU memory (upstreamed to SGLang) and batch-invariant kernels. The result is a model that continuously perceives and responds, with a background model handling deeper reasoning asynchronously.

Benchmarks demonstrate state-of-the-art combined performance: the TML-Interaction-Small model achieves FD-bench v1.5 average quality of 77.8 (vs. 54.3 for Gemini flash live) and turn-taking latency of 0.4s (vs. 1.18s for GPT-realtime-2.0 minimal). On intelligence benchmarks like Audio MultiChallenge, it scores 43.4% APR, outperforming most non-thinking models. The article emphasizes that interactivity must be part of the model itself to scale with intelligence: “For interactivity to scale with intelligence, it must be part of the model itself. With this approach, scaling a model makes it smarter and a better collaborator.” While the demos show impressive capabilities—simultaneous speech, time-aware interruptions, real-time video reaction—community skepticism focuses on the economic moat (the architecture is published openly), the contrived nature of demos, and whether local models will quickly catch up. Some users also express a preference for less chatty AI, highlighting the tension between natural interaction and user control.

"For interactivity to scale with intelligence, it must be part of the model itself. With this approach, scaling a model makes it smarter and a better collaborator."

Key Highlights
  • Time-aligned micro-turns (200ms chunks) enable continuous real-time bidirectional interaction across audio, video, and text.
  • Encoder-free early fusion with lightweight embeddings (dMel for audio, hMLP patches for video) allows end-to-end training from scratch.
  • Interaction model delegates asynchronous deep reasoning to a background model while maintaining real-time presence.
  • State-of-the-art interactivity benchmarks (FD-bench v1.5: 77.8; turn-taking latency: 0.4s) combined with strong intelligence scores.
  • Inference optimized via streaming sessions in SGLang and custom low-latency communication kernels.

Interfaze: A new model architecture built for high accuracy at scale
⬆ 146 pts 💬 35 HN comments

Interfaze introduces a hybrid model architecture that combines task-specific deep neural networks (DNNs/CNNs) with an omni-transformer backbone, targeting high-accuracy, low-cost deterministic tasks like OCR, speech-to-text, translation, and structured output. The design leverages the precision of specialized models—capable of producing bounding boxes and confidence scores—while retaining the flexibility of transformers for reasoning and language understanding. Benchmarks show Interfaze outperforming flash/mini models (Gemini-3-Flash, Claude-Sonnet-4.6, GPT-5.4-Mini) and specialized providers across nine evaluations, including OCRBench V2 (70.7% vs. 55.8%), olmOCR (85.7% vs. 75.3%), and VoxPopuli word error rate (2.4% vs. 4.0%). The model supports a 1M token context window, 32K output tokens, and partial task activation via `<task>` tags to reduce compute. Priced at $1.50/1M input tokens and $3.50/1M output tokens, it aims to fill the gap between costly generalist LLMs and rigid specialized models.

The startup also released the Structured Output Benchmark (SOB) to measure JSON accuracy, where Interfaze claims 79.5% value accuracy. Community reaction is mixed: some users report strong OCR performance on challenging documents (e.g., typewritten pages with distortions), while others flag potential astroturfing due to a single glowing comment from a newly created account (woadwarrior01: 'this sort of astroturfing isn't very encouraging'). Technical discussions probe the architecture—whether it's a mixture-of-agents (fraywing asked 'task-specific MoA with DNN routing?') or a purely architectural fusion (andai: 'LLM with convolutional layers added?'). Real-world tests reveal variability: icemaze found STT worse than whisper for their bot, despite leaderboard claims. Founders (yoeven) clarify it's an API service with enterprise on-prem options, and that fine-tuning is not prioritized but adaptable for niche cases. The launch underscores the tension between benchmark-driven narratives and practical deployment reliability.

Interfaze leads in almost every benchmark against both specialized models and generalist flash/mini models, but community tests reveal real-world accuracy gaps.

Key Highlights
  • Hybrid DNN/transformer architecture targets deterministic tasks (OCR, STT, structured output) with high accuracy and low cost.
  • Outperforms flash/mini models on 9 benchmarks including OCRBench V2 and olmOCR, but real-world STT performance questioned.

Postmortem: TanStack NPM supply-chain compromise
⬆ 865 pts 💬 348 HN comments

On 2026-05-11, TanStack suffered a severe supply-chain attack in which 84 malicious versions of 42 @tanstack/* npm packages were published within six minutes. The attack chained three vulnerabilities: (1) a pull_request_target 'Pwn Request' pattern in the bundle-size.yml workflow, which allowed a forked PR to execute code in the base repo's context; (2) GitHub Actions cache poisoning, where the malicious code wrote to the pnpm store cache key that the release workflow later restored; and (3) OIDC token extraction from the runner's memory, enabling direct publish to npm bypassing the intended workflow step. The attacker reused known techniques from the tj-actions/changed-files compromise and Adnan Khan's 2024 cache poisoning research. The malicious payload harvested credentials from numerous sources (AWS, GCP, K8s, Vault, GitHub, SSH) and exfiltrated them over the Session messenger network. Detection came from external researcher carlini within 20 minutes via a GitHub issue.

Notably, the malware also self-propagated by querying npm for packages maintained by the victim and republishing them with the same injection. The postmortem details that the attacker created a fork renamed to evade detection, used a fabricated commit identity, and force-pushed to hide the malicious commit. TanStack's response included purging all cache entries, deprecating affected versions, engaging npm security to pull tarballs, and hardening workflows with SHA-pinned action refs and repository_owner guards. The incident highlights ongoing issues: GitHub Actions' default cache sharing across trust boundaries, the danger of lifecycle scripts in npm install (the payload ran via prepare script), and the lack of internal alerting. The community reaction was intense, with many calling for a rethinking of CI/CD security defaults, such as disallowing cache writes from pull_request_target jobs and moving to fully isolated release pipelines. The open questions left include whether other TanStack repos use the same pattern and how many users were affected.

84 malicious versions across 42 packages published in 6 minutes, detected externally in 20 minutes.

Key Highlights
  • Attack chained pull_request_target cache poisoning, OIDC token extraction, and npm publish via trusted publisher.
  • Malicious payload harvested credentials from multiple cloud services and exfiltrated over encrypted network.
  • Self-propagation mechanism republished other packages the victim maintained with the same injection.
  • Detection was entirely external; no internal alerting existed.
  • Mitigation requires SHA-pinned actions, restricted cache writes, and isolated release pipelines.
