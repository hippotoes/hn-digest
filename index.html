ChatGPT Images 2.0
⬆ 798 pts 💬 616 HN comments

OpenAI's launch of ChatGPT Images 2.0 marks a significant leap in text-to-image generation, with the new model (gpt-image-2) promising improved visual fidelity, text rendering, and prompt adherence compared to its predecessor and competitors like Gemini 2.0 Flash and Nano Banana Pro 2. However, the technical details remain opaque as the official announcement page is inaccessible, leaving the community to infer capabilities from hands-on testing. Early adopters report mixed results: while the model excels at realistic photography and complex compositions (e.g., 'Where's Waldo' style scenes), it still struggles with precise geometric layouts, such as accurately rendering a 3×3 cube with a missing 2×2 section, or labeling piano keys correctly. Pricing has shifted dramatically—a 1024×1024 image at low quality now costs $0.006 (down from $0.011), but high-resolution outputs (e.g., 3840×2160) can reach $0.40 per image, making it more expensive than Gemini 3.1 Flash on a per-image basis. The model also introduces C2PA provenance metadata, but commenters note that social media platforms routinely strip such metadata, limiting its effectiveness.

The community's reaction is polarized between awe at the model's capability and deep unease about its societal implications. One user described the promo images as 'a slideshow of computer generated images attempting to replicate the amazing things that humans do,' while another noted that 'our eyes can no longer tell us what's real.' The pricing comparison sparked debate: GPT Image 2 lowers entry costs for low-res use but is more expensive for high-res, with one user calculating a 3840×2160 image costs $0.40 vs Gemini's $0.151. Technical tests revealed persistent flaws—the model still produces six-fingered hands and misrenders Chinese characters (e.g., '小笼包' with wrong '笼'). Yet many were impressed by its ability to generate functional mockups for PowerPoint slides and edit existing images with context-aware modifications. The conversation also touched on the ethical training data problem: 'The people who made this possible are not getting a millionth of a cent,' a sentiment echoed across threads discussing artist compensation and open-source code exploitation.

Pricing for a 3840×2160 image is $0.40, more than double Gemini 3.1 Flash's $0.151, yet the model still fails at basic geometric reasoning like drawing a 3×3 cube with a missing 2×2 section.

CrabTrap: An LLM-as-a-judge HTTP proxy to secure agents in production
⬆ 111 pts 💬 40 HN comments

CrabTrap, an open-source HTTP proxy from Brex, aims to secure AI agents in production by intercepting every outbound request and evaluating it against a policy using an LLM-as-a-judge. The proxy supports both static rules and LLM-based judgments, logging each decision. The approach is designed to be lightweight, with setup claimed in 30 seconds, and targets the gap between fully locked-down agents and those with excessive permissions. The proxy escapes policy content using JSON marshaling to prevent prompt injection via policy text, and caps request bodies at 16KB with an LLM warning for oversized payloads.

The HN community reacted critically, with many arguing that LLM-as-judge is a flawed security primitive. A prominent comment noted that '99% secure is a failing grade' (cadamsdotcom), while others pointed out that prompt injection can still succeed if the judge shares vulnerabilities with the agent (ArielTM) or if the attacker shapes the request to influence the judge's context. Several commenters advocated for deterministic ACLs or kernel-level controls instead. Despite the skepticism, some saw value in using the proxy as an audit layer or as a complement to static rules, and a few accused the thread of astroturfing due to overly positive comments.

“99% secure is a failing grade” – cadamsdotcom, capturing the core criticism of using LLM-as-judge for production security.

Key Highlights
  • CrabTrap is an open-source HTTP proxy that uses an LLM to evaluate and block/allow agent requests in real-time.
  • It supports both static rules and LLM-based judgments, with JSON-escaped policies to prevent injection.
  • The proxy caps request bodies at 16KB and gives the LLM a warning for oversized content.
  • Critics argue that LLM-as-judge is non-deterministic and vulnerable to prompt injection, and that 99% security is insufficient.
