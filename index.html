This approach avoids the swap-thrashing and crashes typical of naive memory mapping, exploiting architectural features such as MoE sparsity—where only a subset of experts activate per token—to dynamically stream weights from NVMe with prefetching and a neuron cache achieving 99.5% hit rates. The technical foundation lies in its ability to automatically select inference modes, such as expert-streaming for MoE models or dense-FFN-streaming for non-MoE models, ensuring efficient resource utilization without manual tuning.

Wine 11 rewrites how Linux runs Windows games at kernel with massive speed gains
⬆ 905 pts 💬 320 HN comments

Wine 11 represents a transformative leap in Linux compatibility layers by integrating NTSYNC, a kernel-level driver that directly implements Windows NT synchronization primitives. Historically, Wine depended on user-space approximations like esync and fsync, which leveraged Linux's eventfd and futexes but incurred overhead and semantic inaccuracies in multi-threaded gaming. Developed by Elizabeth Figura and merged into Linux kernel 6.14, NTSYNC exposes a /dev/ntsync device, enabling precise kernel-coordinated thread management without round-trip calls to wineserver. This addresses a fundamental bottleneck where synchronization inefficiencies caused frame stutters and inconsistent performance, rewriting core Wine architecture for the first time since its inception.

Benchmark data reveals staggering gains: Dirt 3's frame rate soared from 110.6 to 860.7 FPS, a 678% improvement, with similar boosts in titles like Resident Evil 2 and Call of Juarez. However, these figures compare NTSYNC against vanilla Wine without esync or fsync; users already on fsync may see more modest, single-digit percentage gains. Concurrently, Wine 11 completes the WoW64 architecture, enabling 32-bit applications to run on 64-bit systems without external libraries, and enhances the Wayland driver with bidirectional clipboard support and display scaling. Coupled with Vulkan 1.4 support, hardware-accelerated H.264 decoding, and over 3,000 bug fixes, these advancements bolster Linux gaming viability, benefiting downstream projects like Proton and potentially accelerating desktop Linux adoption by reducing barriers for Windows migrants.

Dirt 3's performance surged from 110.6 to 860.7 FPS with NTSYNC, showcasing a 678% improvement in synchronization-heavy workloads.

Key Highlights
  • NTSYNC kernel driver provides accurate Windows NT synchronization at the kernel level, eliminating user-space overhead
  • WoW64 architecture completion allows seamless 32-bit application support on 64-bit Linux without external libraries
  • Significant performance boosts in multi-threaded games, with benchmarks showing up to 678% FPS improvements
  • Wayland driver enhancements include clipboard support and display scaling for better compatibility
  • Broad updates cover Vulkan 1.4 support, Bluetooth improvements, and numerous game-specific fixes

⬆ 652 pts 💬 418 HN comments

The Hacker News story reveals a critical supply chain attack targeting LiteLLM, a popular Python library for integrating various large language models. Versions 1.82.7 and 1.82.8 on PyPI were compromised with a malicious .pth file that automatically executes a credential-stealing script upon Python interpreter startup, exploiting Python's site-packages mechanism without requiring an import. The payload is double base64-encoded, collects extensive sensitive data including environment variables, SSH keys, cloud credentials, and more, then encrypts it with AES and RSA before exfiltrating to an attacker-controlled server. This sophisticated attack leverages stealthy techniques, such as the .pth file execution, highlighting systemic vulnerabilities in open-source software distribution and the ease of compromising widely used dependencies through Python's packaging ecosystem.

Analysis from the HN comments indicates the attack originated from a compromised Trivy scanner in LiteLLM's CI/CD pipeline, granting attackers access to PyPI publishing tokens and leading to maintainer account takeovers. The impacted versions have been deleted from PyPI, but the cascade effect extends to downstream dependencies like DSPy and CrewAI, amplifying the breach's scope. Commenters, such as driftnode, note the wild chain of compromise: 'trivy gets compromised, that gives access to your ci, ci has the pypi publish token, now 97 million monthly downloads are poisoned.' This incident has sparked discussions on the need for improved sandboxing, credential isolation, and dependency management practices, with tools like canary files and minimum release ages suggested to mitigate future risks, underscoring broader societal implications for trust in software supply chains.
