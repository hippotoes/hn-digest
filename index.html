#3
Performance per dollar is getting faster and cheaper
⬆ 248 pts 💬 87 HN comments

Wafer's deployment of GLM-5.2 on AMD MI355X GPUs showcases a pragmatic path to high-throughput inference without relying on NVIDIA's scarce Blackwell hardware. By quantizing the base bf16 model to MXFP4 using AMD Quark (with negligible accuracy loss on benchmarks like GSM8K and GPQA-Diamond), and combining this with the sglang inference engine (patched for speculative decode on ROCm), they achieved 2626 tok/s/node aggregate throughput at 2.4 requests per second with ≤5s time-to-first-token, matching 80% of B200 performance at over 2x lower cost. Single-stream throughput reached 213 tok/s using a 5/1/6 speculative decode configuration, made possible by fixing a CUDA-centric header bug in the fused multi-step kernel. The work highlights that AMD's software gap is narrowing, as Wafer required no custom kernels—just framework adaptations and MoE kernel tuning—to achieve competitive performance.

This study underscores a broader shift: while NVIDIA retains a software advantage, the combination of FP4 quantization, speculative decoding, and careful batch-size tuning (switching from TP8 for decode to TP4×DP2 for prefill-bound workloads) can make AMD a viable alternative for cost-sensitive deployments. However, the community remains divided. Commenters like 'hassaanr' and 'p1esk' noted that FP4 quantization often degrades output quality in practice, and Wafer's own evaluation showed a 1% drop on GPQA-Diamond. Others questioned the relevance of headline throughput numbers, noting the 60% cache hit rate assumption and that single-stream performance (213 tok/s) is far from the 2626 aggregate. The broader implication is that cost-driven optimization may trade off model fidelity, and real-world adoption will depend on whether AMD's ROCm ecosystem can deliver reliable, day-0 support without extensive engineering effort.

Wafer achieved 80% of B200 throughput at over 2x lower cost on AMD MI355X, hitting 2626 tok/s/node aggregate with only two trivial code changes to enable speculative decode.

Key Highlights
  • GLM-5.2 quantized to MXFP4 using AMD Quark with minimal accuracy loss; speculative decode yielded ~3x single-stream gain.
  • Switching from TP8 to TP4×DP2 for prefill-bound workloads improved aggregate throughput from 1461 to 2626 tok/s/node.
  • Wafer fixed a CUDA-centric header bug in the fused multi-step kernel to enable deep speculative decode (5/1/6).
  • AMD MI355X costs ~2.75x less than NVIDIA B300; performance per dollar is the key thesis.
  • The community questions whether FP4 quantization is truly lossless in production and whether such benchmarks reflect real-world usage.

#5
Leanstral 1.5: Proof abundance for all
⬆ 234 pts 💬 68 HN comments

Mistral AI released Leanstral 1.5, a 6B active parameter (119B total) Apache-2.0 licensed model that sets new benchmarks in formal verification. It saturates miniF2F, solves 587 out of 672 PutnamBench problems (87% on FATE-H, 34% on FATE-X), and exhibits strong test-time scaling—pass@8 climbing smoothly from 44 at 50k tokens to 587 at 4M tokens. The model is trained via a three-stage pipeline: mid-training, supervised fine-tuning, and reinforcement learning using CISPO across two environments: a multiturn proof loop with Lean compiler feedback and a code agent that edits files and runs bash commands. This design enables long-horizon reasoning, as seen in the AVL-tree time complexity proof that required 2.7 million tokens and 22 context compactions.

Beyond mathematics, Leanstral 1.5 demonstrates practical code verification by automatically discovering 5 previously unknown bugs across 57 Rust repositories via an Aeneas-to-Lean pipeline. One highlighted example is an overflow in the zigzag decoding function of the datrs/varinteger library—an edge case the authors claim testing and fuzzing would typically miss, though several HN commenters disputed this. At an estimated cost of $4 per problem (vs $300+ for Seed-Prover 1.5 high), the model makes formal verification far more accessible. The release includes open weights on Hugging Face and a free API endpoint, targeting both researchers and practitioners. Community reaction is mixed: some praise the democratization of proof engineering, while others question the novelty of bug discoveries and the fairness of benchmarks compared to older models.

Saturates miniF2F, solves 587/672 PutnamBench problems, and finds 5 previously unknown bugs across 57 repositories at $4 per problem—vs $300+ for comparable systems.

Key Highlights
  • Saturates miniF2F and achieves state-of-the-art on FATE-H/X (87%/34%).
  • Demonstrates strong test-time scaling: from 44 to 587 PutnamBench problems as token budget increases.
  • Discovers 5 previously unknown bugs in open-source Rust code via automated Lean translation pipeline.
  • Cost-effective at ~$4 per problem—orders of magnitude cheaper than comparable provers.
  • Fully open-source (Apache-2.0) with free API and Hugging Face weights.

The article details BIOS tweaks (forcing Gen4, disabling ASPM), kernel parameters (iommu=off, ACS disable via setpci), and GPU power limiting to 350W each to run on a 110V circuit. The statistical correlation is stark: prior to Mythos's public release in April 2026, the monthly baseline for high-severity CVEs from notable vendors was around 300–400. The article draws lessons for public grocery initiatives, such as New York City's proposed public stores, suggesting they emulate Costco's low SKU count and a signature loss leader (e.g., a $2.12 halal wrap). Notably, Costco's revenue has grown over 10% annually for five years, despite minimal e-commerce investment. The piece concludes by tracing Costco's lineage to Fedco, a public-sector cooperative, framing its model as a scalable blueprint for socially responsible retail that prioritizes simplicity over logistical heroics.

Costco's 4,000 SKUs (vs. Amazon's endless aisle) and 6% employee turnover (vs. Amazon's 150%) prove that constraint, not complexity, can be the foundation of a retail juggernaut.

⬆ 202 pts 💬 93 HN comments

New research from the University of Exeter and Cardiff University, published in Science, challenges a long-held assumption that the tallest trees struggle to transport water to their uppermost branches. By examining Dipterocarp trees ranging from 7 to 71 meters in Malaysian Borneo, the team discovered that hydraulic systems fully compensate for height. Adaptations include wider water-carrying vessels near the ground and leaves that withstand greater water stress before wilting.
