Show HN: Needle: We Distilled Gemini Tool Calling into a 26M Model
⬆ 472 pts 💬 154 HN comments

Needle is a distilled 26-million-parameter model designed specifically for single-shot tool calling, compressed from Gemini 3.1 via a novel Simple Attention Network architecture that eliminates all feed-forward layers (FFN). This radical simplification — using only attention, tied embeddings, and a GQA+RoPE encoder-decoder stack — reduces the model to such a small footprint that it can run on CPUs or low-power edge devices. On Cactus hardware, Needle achieves 6000 tokens/sec prefill and 1200 tokens/sec decode, making it viable for real-time inference on phones, watches, and even glasses. The model's weights, training code, and synthetic data generation pipeline are fully open source under MIT license.

Trained on 200B tokens of general text then fine-tuned on 2B tokens of synthetic function-call data, Needle outperforms larger alternatives like FunctionGemma-270M and Qwen-0.6B in one-shot tool use, though it lacks the broader conversational capabilities of those models. The authors note that MLPs are unnecessary when the model relies on an external knowledge source. Community testing reveals impressive results for simple commands (e.g., setting timers, querying weather) but failures on ambiguous or multi-step tasks — for instance, one user reported it chose 'set_timer' instead of 'send_email' when told 'I will be late'. Despite these limitations, the model's tiny size (14 MB in INT4) opens the door to fully local, privacy-preserving AI assistants on constrained devices.

A 26M-parameter attention-only network that runs at 1200 tokens/sec on edge devices, outperforming models 10x its size in single-shot function calling.

Key Highlights
  • 26M parameter Simple Attention Network with zero feed-forward layers, distilled from Gemini 3.1
  • 6000 toks/sec prefill and 1200 toks/sec decode on Cactus hardware; 14 MB in INT4
  • Outperforms FunctionGemma-270M, Qwen-0.6B, Graninte-350M on single-shot function calls
  • Fully open weights, training code, and data generation pipeline on GitHub and Hugging Face
  • Designed for on-device AI on phones, watches, glasses, and other resource-constrained devices

Reimagining the mouse pointer for the AI era
⬆ 206 pts 💬 173 HN comments

Google DeepMind has introduced a conceptual AI-enabled pointer that leverages Gemini to understand not just where the user is pointing, but the semantic context of the target. The system captures visual and semantic information around the cursor, enabling users to issue natural-language commands like “show me directions” over an image, or “double the ingredients” on a recipe, without explicit prompting. This approach is built on four interaction principles: maintaining user flow across applications, using “show and tell” to infer intent via pointing, embracing vague deictic references like “this” and “that”, and turning pixels into actionable entities (e.g., a scribbled note becomes an interactive list). The prototype is integrated into Chrome and a new Googlebook laptop, with demos running in Google AI Studio and Labs.

The concept aims to eliminate the friction of dragging content into separate AI windows, instead making AI omnipresent and context-aware. However, technical implementation raises unresolved questions: the system likely relies on constant server-side processing of screen content, as local models may not be powerful enough. Privacy implications are severe—reminiscent of Microsoft Recall—as continuous screen capture could be exploited for advertising or legal discovery. The demos themselves appear slow and imprecise; one comment notes that simply selecting text and right-clicking is faster. Historically, these “put that there” paradigms date back to the 1980s, yet never achieved mainstream adoption due to social and interaction costs. The viability hinges on latency, accuracy, and user willingness to speak commands in public or private spaces.

“The mouse pointer has barely evolved in more than half a century… we want intuitive AI that meets users across all the tools they use, without interrupting their flow.”

Key Highlights
  • Google DeepMind's AI pointer uses Gemini to infer semantic context from cursor position and voice commands, aiming to reduce need for explicit prompting.
  • Four design principles: maintain flow, show-and-tell, embrace vague references, turn pixels into entities.
  • Prototype integrated into Chrome and Googlebook, with demos in Google AI Studio.
  • Major concerns: always-on screen capture sends data to servers, similar to Microsoft Recall.
  • Voice-centric interaction impractical in open offices or public spaces, and may be slower than existing keyboard/mouse workflows.

The episode underscores a growing tension between proprietary cloud-dependent hardware manufacturers and the open-source community, especially when the manufacturer's own software is built on open-source foundations (PrusaSlicer) but increasingly restricts user autonomy.

The developer's response highlights the absurdity: they claim their modification simply used the same AGPL-licensed code from Bambu's own Linux client. Bambu justified the crackdown by citing service outages from 'unauthorized traffic spikes,' yet critics note that relying on a user-agent string for infrastructure security is laughably weak. Jeff Geerling, who documented the saga, points out the irony that Bambu's own fork once caused telemetry to hit Prusa's servers without legal retaliation. The community's reaction has been swift: Louis Rossmann pledged $10,000 to the developer's legal defense, and many users are reconsidering purchases. This incident exemplifies the battle over ownership in the Internet of Things era, where a physical purchase does not guarantee control over the device's operation.

Bambu Lab's blog blamed unauthorized traffic peaks on user-agent spoofing, a security measure that one commenter called 'so crazy of an excuse that I don't believe it.'

Why senior developers fail to communicate their expertise
⬆ 590 pts 💬 259 HN comments

The article dissects a core tension in software engineering: senior developers prioritize complexity management to ensure system stability, while the rest of the business focuses on uncertainty reduction through rapid experimentation. This misalignment causes communication failures, as seniors speak in terms of 'no, that adds complexity' when others need speed to validate market hypotheses. The author, a copywriter, frames the problem as a copywriting issue: messages must be tailored to the audience's monster (complexity vs. uncertainty). Seniors are portrayed as 'avoiders, reducers, recyclers' who instinctively resist new code because every addition risks degrading understandability, debuggability, and long-term maintainability—the very attributes that keep paying customers happy. The proposed solution is a simple reframing: instead of saying 'no,' ask 'Can we try something quicker?' This acknowledges the business's need for speed while allowing seniors to exercise their expertise in reuse and minimalism.

The article extends this framework to AI, arguing that large language models are powerful accelerators for the 'speed loop' but threaten the 'stability loop' by flooding codebases with unowned, incomprehensible code. To reconcile both loops, it suggests decoupling the system into a 'Speed' version (for rapid prototyping, AI-heavy, disposable) and a 'Scale' version (senior-curated, stable, and understandable). This echoes the 'throw one away' advice from The Mythical Man-Month but adapts it for the AI era. Hacker News comments deepen the analysis: some argue that expertise is tied to an internal 'world model' that cannot be fully transmitted, while others critique the article's binary depiction of senior developers. Many highlight that organizational incentives (e.g., feature-driven metrics) override any reframing, and that AI's destabilizing effect is real but addressable through process changes rather than dual codebases. The discussion reveals a community actively grappling with how to preserve engineering craftsmanship in an age of accelerated delivery.

"Senior developers talk in terms of complexity when everyone else is worried about uncertainty. The magical phrase every senior must learn: 'Can we try something quicker?'"

Key Highlights
  • Senior developers focus on complexity management (stability) while the business seeks uncertainty reduction (speed), leading to a communication gap.
  • The article proposes reframing senior objections as 'Can we try something quicker?' to align with business needs while leveraging reuse and minimalism.
  • AI accelerates the speed loop but destabilizes the stability loop by adding unowned, incomprehensible code; decoupling into Speed and Scale versions is suggested.
  • Commenters highlight that expertise is often tacit and embedded in internal world models, making full communication impossible.
  • Organizational incentives and power dynamics often override technical arguments, making the reframing insufficient without structural changes.

Rendering the Sky, Sunsets, and Planets
⬆ 478 pts 💬 39 HN comments

This article presents a comprehensive, step-by-step guide to rendering realistic atmospheric scattering in the browser using WebGL shaders. The author builds from first principles: raymarching through a volumetric medium, accumulating optical depth via Rayleigh and Mie density functions, computing transmittance with Beer's Law, and applying phase functions to distribute scattered light toward the viewer. The implementation extends to include ozone absorption for twilight hues and a secondary light-march to model sunlight attenuation along the sun-sample path, enabling accurate sunrise/sunset colors. The shader is then adapted into a full-screen post-processing effect that reconstructs world-space coordinates from the depth buffer, allowing the atmosphere to interact with 3D geometry as a volumetric shell around a planet.

The article is accompanied by interactive WebGL widgets that let the reader adjust parameters like altitude, sun angle, and scattering coefficients in real time, demonstrating the visual impact of each component. The author credits key references: Sébastien Hillaire's production-ready sky rendering technique, the work of Shota Matsuda on geospatial atmospheric rendering, and classic papers by Nishita et al. (1993) on atmospheric scattering. The Hacker News comments reveal a deeply engaged audience: some discuss the missing twilight model (sky shouldn't go black immediately after sunset), others recall implementing the original Nishita paper, and many share links to their own projects (SpaceEngine, planetary generators, Godot plugins). The post is a masterclass in bridging physical optics and real-time graphics, with clear code examples and aesthetic results.

The author's interactive demo shows that without a light-march loop, moving the sun close to the horizon yields only a 'white, hazy glow' — the sunset colors emerge only when the shader accounts for light attenuation along the path from the sun to each sample point.

The debugging effort was extensive: engineers instrumented qlog output and built visualizations to reveal the death spiral, which only manifested under a perfect storm of conditions—minimum cwnd, congestion avoidance active, and a prior loss event that set the recovery boundary. The fix itself was elegant and minimal: measure the idle duration from the last ACK timestamp rather than the last packet send, preventing the recovery boundary from being prematurely advanced. This change restored a 100% pass rate in integration tests, reducing completion time from >10 seconds (61% failure) to ~4–5 seconds.
