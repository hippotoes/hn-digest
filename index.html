Bonsai 27B: A 27B-Class model that runs on a phone
⬆ 598 pts 💬 211 HN comments

PrismML's Bonsai 27B marks a significant breakthrough in model compression, achieving the first 27B-parameter model capable of running on a phone. Building on Qwen3.6, the model uses ternary (−1,0,+1) and binary (−1,+1) weights with FP16 group-wise scaling, yielding effective bit widths of 1.71 and 1.125 bits per weight respectively. This compression reduces the model size from ~54GB (FP16) to 5.9GB (ternary) and 3.9GB (1-bit), while retaining 95% and 90% of full-precision benchmark performance across math, coding, and agentic tasks. The key innovation is end-to-end low-bit representation across all components, with no higher-precision escape hatches. This enables the 1-bit variant to fit within the constrained memory budget of devices like the iPhone 17 Pro, opening the door for sophisticated on-device AI agents.

The benchmark results show minimal degradation in critical areas: math drops only 1.9% (ternary) and 3.6% (1-bit), while coding drops 2.7% and 6.8%. However, tool calling sees a larger 6-14% decline, a point of discussion in the comments. The model achieves up to 163 tok/s on an RTX 5090, making it viable for interactive use. Community reactions are mixed: enthusiasts celebrate the 'intelligence density' metric (0.53 per GB, 10x the baseline) and practical implications for privacy and offline agents, while skeptics question benchmark validity and note real-world issues like '!!!!!!!!' outputs on Android. Early adopters report decent performance on CPU (6 t/s binary) but note that ternary CPU inference is unoptimized. Comparisons to Gemma 4 12B's QAT version show Bonsai winning on math/coding but losing on vision, highlighting the tradeoffs in extreme quantization.

1-bit Bonsai 27B delivers 0.53 intelligence per GB, over 10x the full-precision baseline and approximately 2.7x the best low-bit alternative.

Key Highlights
  • Two variants: Ternary (5.9 GB, 95% retention) and 1-bit (3.9 GB, 90% retention).
  • Runs on devices from laptops to iPhone 17 Pro, with up to 163 tok/s on RTX 5090.
  • Supports 262K token context, multimodal vision, and agentic tool use.
  • Models available under Apache 2.0 license on Hugging Face.
  • Represents a paradigm shift for on-device agentic AI, reducing cloud dependency.

LeMario: Training a JEPA World Model on Super Mario Bros
⬆ 99 pts 💬 13 HN comments

LeMario is a reproduction of LeWorldModel, a Joint-Embedding Predictive Architecture (JEPA) that learns world dynamics from pixels and actions, applied to Super Mario Bros. The model uses a vision encoder to compress frames into 192-dimensional latents, an action encoder for button sequences, and a causal predictor with Adaptive LayerNorm Zero (AdaLN-Zero) to condition predictions on actions. Training on 737,134 frames from 280 episodes across 32 levels yielded strong short-horizon dynamics: LeMario achieved a 45.5% lower five-step prediction error than a persistence baseline, and shuffled actions increased error by 47.5%, proving the model learned action-conditioned prediction. However, when used for reward-free planning via the Cross-Entropy Method (CEM) with a goal image, Mario barely moved for nearby goals and failed to overcome obstacles for distant ones. The author systematically probed the latent space, discovering that horizontal position was recoverable with R²=0.997, but vertical position was weak (R²=0.188), and that CEM exploited visual similarities caused by the scrolling camera.

The failures reveal a fundamental mismatch between predictive state and control state: the encoder optimizes for predicting future frames, capturing camera position, enemy phases, and HUD details, but not for representing controllability. CEM, doing exactly what it was asked, found action sequences that minimized latent distance to the goal, often by exploiting visual lookalikes rather than making progress. The author notes that the original LeWorldModel succeeded under conditions that did not transfer: nearby goals, fixed camera, smooth movement, and extensive expert data (20,000 episodes vs. 280). Chunking the goal into intermediate checkpoints improved progress but did not fix latent distance as a brittle metric. The article concludes with three lessons: predictive state is not control state, CEM searches for model weaknesses, and environment assumptions matter as much as architecture. The community engaged deeply, with commenters like lucrbvi calling it 'such a gem' and rsfern highlighting challenges of long-horizon planning, while others like enjeyw and joblessjunkie pointed out JEPA's lack of importance weighting and the need for action-oriented goals.

Predictive state is not control state — the encoder treats camera position and enemy phase as equally important as Mario's coordinates, making latent distance a brittle measure of progress.

Key Highlights
  • LeMario reproduces LeWorldModel's JEPA architecture and trains on 737k frames of Super Mario Bros. gameplay.
  • It achieves strong short-horizon prediction (lower error than persistence and shuffled-action baselines) but fails at reward-free planning over long distances.
  • Probing reveals that horizontal position is well-represented in latent space (R²=0.997) but vertical position is poor (R²=0.188).
  • CEM exploits visual similarities from the scrolling camera, causing the planner to converge on lookalike locations rather than true progress.
  • The author emphasizes that dataset scale, environment assumptions (fixed vs. scrolling camera), and evaluation metrics are as critical as the architecture itself.

The Tower Keeps Rising
⬆ 468 pts 💬 223 HN comments

Armin Ronacher's essay uses the Tower of Babel as a metaphor for the subtle risks of AI-assisted software development. He argues that while agents dramatically boost individual productivity, they erode the shared language—conceptual boundaries, invariants, ownership—that enables large-scale coordination. Historically, friction in code reviews and cross-team communication forced developers to build a common mental model of the system. Agents circumvent this friction, allowing changes to land without human synchronization, so construction continues even after shared understanding collapses. The tower keeps rising, but the architecture becomes an incomprehensible Babel. Ronacher notes this is distinct from the biblical story: failure is not immediate, making the loss invisible until too late.

The Hacker News discussion amplifies these concerns. Commenters lament that vibe-coded software suffers from inconsistent validations, redundant operations, and hidden complexity—'the horror that lurks in these Python files.' Others draw parallels to the Lisp Curse, where ease of individual creation hinders collaborative tooling. A recurring theme is that AI productivity gains transfer the bottleneck from writing code to maintaining shared comprehension. Some propose new rituals, like mission-control-style collective agent steering, or discipline akin to 'not letting the agent scratch every itch.' The essay's central insight—that coordination, not code generation, is the true constraint—resonates deeply, challenging the naive narrative of AI as a simple multiplier.

"The tower does not fall, and so we do not notice what was lost. It just keeps rising."

Key Highlights
  • Agents remove synchronization friction, allowing construction without shared understanding.
  • Coordination, not individual coding speed, is the true bottleneck in large projects.
  • Vibe-coded codebases exhibit chaotic growth and hidden complexity.

Cursor 0day: When Full Disclosure Becomes the Only Protection Left
⬆ 364 pts 💬 171 HN comments

Mindgard disclosed a critical 0-day in Cursor, the AI-powered IDE boasting 7M+ active users and a $60B valuation. On Windows, Cursor locates the git binary by searching the current workspace directory before PATH. An attacker who places a malicious git.exe in a repository's root can achieve arbitrary code execution without any user interaction—no prompts, no dialogs, not even the workspace trust gate. The proof-of-concept simply renamed Calculator.exe to git.exe, and Cursor launched it repeatedly on every open. The vulnerability was reported to Cursor on December 15, 2025, through their security.txt channel and later via HackerOne after the CISO acknowledged an automation failure. Despite reproduction and confirmation by HackerOne, Cursor has shipped over 197 versions in the intervening seven months without a patch, effectively ignoring the researchers and leaving users exposed.

The article's timeline shows multiple follow-ups met with silence, leading to full public disclosure as a last resort. Commenters on Hacker News are sharply divided. Some argue the bug is actually a Windows architectural quirk—Windows includes the current directory in its executable search order unless explicitly removed—and that the real issue is Microsoft's decades-old design. Others counter that responsible software should explicitly resolve full paths to trusted binaries, as Go's os/exec does. A third cluster criticizes the AI-generated prose of the blog post and questions Mindgard's motives, suggesting the disclosure is more about marketing than user safety. A fourth group highlights the amplified risk in an AI-agent context: when coding agents autonomously clone and inspect repositories, a planted git.exe could compromise hundreds of thousands of endpoints in a supply-chain style attack. Cursor's silence is particularly troubling given its reliance on trust for agentic code execution.

197+ versions shipped without fixing a trivial arbitrary code execution bug — Cursor silently executed a renamed Calculator from any untrusted repository.

Key Highlights
  • Cursor on Windows runs `git.exe` from the project root without user consent, enabling RCE.
  • Mindgard reported the issue in December 2025; Cursor acknowledged via HackerOne but never fixed it.
  • Over 197 versions released since disclosure; no patch or communication from Cursor.
  • Exploitation requires only a malicious `git.exe` in a cloned repository — trivial for attackers.
  • AI agents that autonomously clone repos amplify the risk to supply-chain scale.
